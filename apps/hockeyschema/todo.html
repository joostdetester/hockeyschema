Tagging-schema

risk-based · vastgesteld

Elk scenario krijgt een type-tag (@ui/@api/@accessibility/@e2e/@db) plus precies één risico-tag uit onderstaande vier-punts-schaal. @smoke blijft daarnaast bestaan als losse, orthogonale vlag ("snelle sanity-check die op elke build moet slagen") — een scenario kan dus @ui @critical @smoke zijn.

TagBetekenis
criticalBug hier = de coach zit er tijdens de wedstrijd mee vast (schema kwijt, live score/DP fout, kan niet opslaan). Draait op elke build/PR.
highBelangrijke functionaliteit, geen wedstrijd-blokkerende impact maar wel vervelend/zichtbaar.
mediumNuttig maar minder tijdsdruk — normale regressie.
lowRandgevallen, cosmetisch, zelden gebruikte paden.

Prioriteitsvolgorde: 1. Live/Wedstrijdmodus + Wedstrijdschema (kernflows tijdens de wedstrijd zelf) — 2. Team + Strafcorner — 3. Programma + Standen + Historie — 4. Ouders + Notities.
